# ADR-322: Publish attributed cross-sectional walk-forward diagnostics

- **Status:** Accepted
- **Date:** 2026-10-19
- **Deciders:** Codex autonomous session 1, ISO 2026-W43
- **Extends:** ADR-024/035/145/150/293/321
- **Addresses in part:** FINDING-265

## Context

ADR-321 now measures and persists panel family walk-forward diagnostics, but the
read-only cross-sectional endpoint projects only headline and IC metrics. The
panel therefore cannot show those measurements. A separate validation-report
renderer does not publish this endpoint's evidence. Independent frontend review
supports an additive publication slice preserving attribution and legacy absence.

## Decision

Add trial walk_forward_oos_sharpe and experiment walk_forward_method,
walk_forward_hold_sharpe, walk_forward_n_bars and walk_forward_n_splits to the
existing latest-experiment API view. Project the exact stored values, without
reselection, recomputation, invented geometry or historical backfill. All new
fields are nullable with compatibility defaults. Reconstruct the concrete source
experiment before projection so unchecked copies cannot issue contradictory
claims. The public view enforces finite added statistics, the recognized ADR-321
literal and the same complete measured/legacy metadata branches. Geometry uses
original nonboolean Integral counts normalized through the unchanged shared guard.
Method-present views require nonempty trials, every family mean, finite common
benchmark and actual positive split count with bars >=splits+1. Method absent
permits legacy unpaired trial scalars and requires absent pairing/geometry.

Mirror the additive contract at the existing Zod network boundary, including
structural completeness and finite/representable geometry. Client checks validate
wire identity, never rederive graduation or scientific scores. Old omitted/null
payloads remain readable. Unknown methods and malformed partial measured payloads
fail through the existing error state instead of silently dropping metadata.

Keep the existing panel/table style and add one Walk-forward mean Sharpe column.
Present zero and signed measured values normally. Null/omitted scalar says
not measured. A legacy method-null nonnull scalar is explicitly legacy, unpaired;
never pair it to a benchmark, display invented excess or assign a method to it.
For attributed rows, show the common equal mean of same-window universe benchmark
Sharpes and actual search-bar/window counts. Do not display the raw recipe literal
or internal report/store mechanics in the user flow.

Visible concise qualifications retain the ADR-321 meaning: selection within each
family uses earlier training rows, while the overall winning family uses the
complete search sample; these are continued-config window scores with internal
costs but without account entry/switch reconciliation; the equal-weight universe
benchmark has no added turnover-cost model; supplied fundamental maps are static
snapshots, not historical point-in-time information. Scores are equal means of
window Sharpes, not Sharpe on stitched policy returns. Purged CV remains not
measured, without inventing historical fold counts.

No evaluator, selector, threshold, accounting-v14, candidate, holdout, generated
record, calibration cohort or workflow changes. F265 stays open for purged
measurement and its dependency/embargo design. This slice closes public WF
publication only.

## Alternatives

1. Add attributed paired fields and a compact table/caption: chosen, coherent
   backend-to-client evidence without a new endpoint or redesign.
2. Publish only a raw family scalar: rejected; historical values lack method and
   pairing and could be mistaken for current measured evidence.
3. Add excess/selection/significance styling: rejected; introduces unsupported
   inference or ranking beyond the published statistic.
4. Replace compact persistence with full reports/config maps: separate larger
   audit-trail decision, not required for faithful compact publication.

## Verification and reversal

Observe backend and frontend RED before source edits. Test exact latest-record
wire values across multiple measured families, zero/negative scores, legacy
null/unpaired rows, empty/missing pools, source-copy reconstruction and measured
view completeness/finite/method/original-geometry refusals. Frontend tests cover
schema preservation, malformed metadata rejection through the real service,
measured caption/geometry, honest legacy/null cells, methodology limits and
existing loading/error/empty/graduate/IC behavior. Keep existing tests intact.
Independent scientific/frontend review and foreground make check-all precede
individual commit/fresh sync/push and exact master CI. Confirm all research core
modules, generated bytes, thresholds and existing primary view values remain.

Reverse by removing additive projection/display together, while retaining the
underlying persisted measurements and F265's written evidence. Historical data
must never be rewritten or relabeled as part of reversal.
