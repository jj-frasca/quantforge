# FINDING-248: Displayed calibrations lack current-procedure attribution

- **Status:** Resolved by ADR-294
- **Date:** 2026-10-16
- **Scope:** API/dashboard attribution of retained null and power measurements
- **Governing decisions:** ADR-044/053/065/158/291/294

## Reproduction and impact

On delivered revision `9202fa6449a974b8f916d9a204b08fa843d72ec7`, the null and
power list endpoints parse historical artifacts without comparing their recorded
search/gate fingerprints or history with the deployed default. The dashboard
renders them beside the live pool headline. Null rows expose only stored search
prefixes; power sweeps expose neither fingerprint and say they use the same
history as a real hunt. Available real-symbol history varies.

Independent session-17 frontend review reproduced this display with manually
authored obsolete-identity React SSR fixtures. The actual committed metadata
confirms the mismatch: all eight null artifacts and both power sweeps (all twelve
nested cells) have a different search fingerprint from the current full-34 v14
default, despite matching GateConfig hashes. Six nulls and both sweeps record
`3f36fda20f9ddc5469e3ae45b173ba699902d5c00d5c7523af8ef061ddaa14eb`;
the two 7400-bar nulls record
`4140981ffc8e2e0e73cb3477259dca97d82d019741c212e25efadbdf9f957501`.
The current default reference is
`edb65cb596b9c2daabe2ba81bf5660a562dfc110beefcb16d493244679ad2459`,
gate `250856983fb58b7f0392157eef5c96960a26d0b2b3f81d063281bf6b18eeb493`,
with target calibration history 7400 bars. This comparison computes public
fingerprints without running a search or calibration. Session 19 separately
confirmed the committed top-level identities read-only.

These are valid historical measurements for their recorded procedures. No wrong
historical arithmetic, false graduate, threshold defect or changed calibration
rate is established. The defect is that missing consumer context can attribute
historical evidence to a different current procedure. A custom selector or
history may intentionally differ from the default without being invalid.
Existing pool/null comparability guards answer a separate matched-pool question
and remain intact.

## Containment and correction

ADR-294 adds presentation-only per-artifact compatibility beside the same parsed
numbers, with one captured current-default reference per request. Search, gate
and exact complete history each report MATCHED, DIFFERENT or UNKNOWN. A known
mismatch dominates missing information; missing/sentinel lineage or unavailable
reference never defaults to a match. Power checks include every nested cell's
own identity and complete history as well as its sweep header.

Historical values, ordering, list contracts and missing-directory semantics stay
available. Scientific artifact models and generated bytes are preserved. Old
servers without metadata display UNKNOWN. Both panels show a qualification next
to the relevant row/sweep, recorded/current identity details and measured history;
the power caption no longer asserts matching real-hunt history. Compatibility
means matching recorded procedure/history only, without scientific certification,
market-wide Type-I bounds, power under other laws or ADR-102 authorization.
No search, new measurement, threshold, accounting, source or cohort change is
part of this correction. F247's incomplete bootstrap remains separately preserved.

## Verification and limits

Pre-implementation evidence: `/tmp/qf-w42-s17-frontend-calibration-review.md`,
`/tmp/qf-w42-s17-frontend-review.cjs` (four manual SSR groups), and
`/tmp/qf-w42-s17-calibration-freshness-metadata-v2.json` (identity/history only).
Independent research and frontend review approved the prospective ADR-294 scope.
Behavioral TDD first observed two API failures on missing compatibility and ten
frontend failures on stripped metadata, malformed metadata acceptance and missing
unknown qualification. Additional malformed-root/JSON preservation regressions
failed before correction. Focused verification passed 57 backend tests (39 new
plus 18 existing endpoint tests) and 111 frontend tests across six suites; lint,
formatting and strict typing passed. A later compact-layout wording change also
observed nine assertion failures before correction and retained all 111 tests.

Parent read-only API audit checked the actual eight null artifacts and two power
sweeps: every pre-existing serialized field, value and list order agrees exactly
with the scientific model, and every generated byte is unchanged. All 999 tracked
data/research/validation/data-layer/unit-test files in its preservation baseline
remain byte-identical. Current default fingerprints remain those above. Receipt:
`/tmp/qf-w42-s19-compatibility-parent-audit.json`. No active frozen-cohort outcome
was read and no search or calibration was invoked.

A local installed headless browser rendered manual fixtures using the actual
components and CSS at 1280px and 390px. Compact qualifications retain visible
status/dimensions/target, expandable reasons/identities/settings and readable
minimum width. Both tables scroll within their panels; expanded hashes and
catalog text do not overflow their comparison containers. The page width equals
the viewport at both sizes. Screenshots and layout receipt:
`/tmp/qf-w42-s19-ui-{desktop,mobile}.png` and
`/tmp/qf-w42-s19-ui-layout.json`. This is component/layout verification, not a
full live-app end-to-end test. The in-app browser was unavailable.

Independent research review approved the implemented attribution and written
scope; frontend review and parent visual inspection approved the compact layout.
Full foreground `make check-all` passed 11,415 backend tests (97.37% coverage)
and 381 frontend tests (97.66% statement coverage), with lint, formatting and
strict typing green. No verification remained open before commit.
Local scratch retention is not guaranteed; this finding preserves the issue and
reproduction shape independently of those temporary files.
